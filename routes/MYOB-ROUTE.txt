MYOB ROUTE PROCEDURE FILE - routes/MYOB-ROUTE.txt (judge-bas-review, release V1.3). This file is part of the BAS review agent's instructions: once fetched as set out in ROUTE PROCEDURE FILES in the system prompt, follow it exactly as if it were the section named MYOB ROUTE in that prompt. Section references (WORKFLOW, PRE-REVIEW MODE, STEP 4, TOOLS, usage block) point to the system prompt.

MYOB ROUTE (BAS prepared in MYOB; 5 November 2026)
MYOB clients' BASs are reviewed from a MYOB export pack the Preparer attaches to an update on the AS Task, not from the client's Xero Ledger file: ignore any Xero Ledger file and Xero Tenant ID the client has. Everything above still applies (SESSION, SECURITY, MEMO JSON CONTRACT, EXECUTIVE SUMMARY CONTENT, STYLE, PRE-REVIEW MODE outcomes, update first lines, PAYGI choice check, Override unreconciled, loop limit, usage block) except where this section changes it. Never call TOOLS items 2, 3, 4, 6 or 7, and never write a Xero link. There is no bundle and no API: read the pack with python in /tmp/myob/ and compute everything yourself.

Y1. DATA
From AS task files, download: the newest MYOB export pack (a zip attached to an update, named "MYOB Export - <Client> - <Mon-YY>.zip"; newest by created_at; if packs for more than one period are attached, use the newest whose reports cover the Task's BAS period and say so in Sources), the current AS PDF (T2/T7, due date, document ID), the prior lodged AS, the ATO ICA CSV (unzip it if it is inside a zip), FTC details where the client claims fuel tax credits, and a client fixed asset register if one is attached. Unzip the pack with python zipfile into /tmp/myob/. Excel or CSV reports are the primary source where present; read a PDF report with text extraction, or visually where the text cannot be extracted. Inspect each file's layout before parsing; never assume a column you have not seen. The pack:
1. Coding report (BAS period) - always: Section 1 and test (a). It lists transactions not yet allocated (coded) in MYOB; an empty report means every transaction in the period is coded.
2. GST report, detail, on the client's GST basis (BAS period) - always: Sections 4, 7 and 9. Every transaction with its MYOB tax code.
3. GST return report (BAS period) - always: Section 7 cross-check of G1, 1A, 1B.
4. General ledger report, detail (BAS period) - always: Sections 1 (duplicates), 2, 3 (General Expenses transactions), 5 and 9.
5. Trial balance (as at period end) - always: Sections 1, 2, 4, 5 and 6. Never use its income and expense lines for Section 3: if the MYOB financial year has not been rolled over they can be cumulative across years.
6. Profit & Loss (BAS period, compared with the previous period of the same length) - always: Section 3.
7. Lock date screenshot (Business details page showing the business name and the Lock date section; the Financial year section too) - always: the Lock Periods line and the identity check.
8. Receivables reconciliation with tax (as at period end) - only when trade debtors in the Trial balance is non-zero: Section 4.
9. Payables reconciliation with tax (as at period end) - only when trade creditors in the Trial balance is non-zero: Section 4.
10. Payroll summary report (the withholding period or periods inside the BAS period) - only when the client has payroll: Sections 7 and 8.
11. Audit trail (changes after period end to transactions dated in or before the period) - optional, never a failure: the Lock Periods line and Section 5.
A missing report: proceed and flag the limitation in the sections that use it, except where Y5 says otherwise. The Banking reconciliation report is not part of the pack: MYOB clients often allocate through the bank feed without ticking items off or entering a statement balance, so its "Date last reconciled" and outstanding items are not reliable; if one is attached anyway, do not use it for any test. Never reproduce the client's contact details (email, phone, address) from the screenshot or report headers in the memo, an update or a file name.

Y2. IDENTITY AND PERIOD
The business name on every report and on the lock date screenshot must be the client on the Task (allow for a trading name or "Pty Ltd" wording; if it is not clearly the same business, it is a mismatch), and the date range on every period report (the as-at date for the Trial balance and the two reconciliations, the withholding period for the Payroll summary) must match the Task's BAS period. Any mismatch (for example a pack run for the previous quarter): post an update saying exactly what does not match, add the usage block, set Status to In Progress and stop (prereview: the update's first line is "Pre-Review recheck - <Period> - NOT COMPLETED", recheckOutcome "not_completed").

Y3. GST BASIS
The client's basis is the one shown on the current or prior ATO Activity Statement (for example "GST cash"); if neither states it, use the basis printed on the GST report and say so. The GST report must have been run on that basis. If it was run on the other basis, do not convert it: flag "GST report run on the wrong basis" (Medium, Section 4), still complete the review on the report as provided, and ask for a re-export in the completion update. Period meta row: "GST basis: <Cash/Accrual> - <source: current AS / prior AS / GST report>".

Y4. CODING REPORT GATE (Claude runs it; the Make gate checks the documents only)
On the pack being used: the Coding report has no unallocated transaction dated on or before period end. In review mode a failure does not stop the review: Section 1 is High and Bank Rec Completed = No, with an item covered by a valid Override unreconciled update shown as Medium (Y5 Section 1). In prereview mode this is test (a).
Account-wide Override unreconciled (9 November 2026; PRE-REVIEW MODE test (a), system prompt v15): the update names a Trial balance bank or card account and covers the unallocated Coding report items on it dated on or before the cut-off date. The gate checks author and format only and posts "Override unreconciled applied (count to be checked by Claude): ...". At the first review or recheck after that acknowledgement, count those items in the pack being used and sum their absolute amounts. If both equal the update, those items (date · description · amount · account) are the frozen set: list them in the Section 1 table (Y5). Later reviews and rechecks cover only items in that list, taken from the Section 1 table of the latest memo. A fresh pack does not reset the frozen list: an item in a later pack that is not in the list is not covered, even on the same account and before the cut-off date. If either figure differs, the override is not valid: say so on the test (a) line (or in Section 1 in review mode) with your count and total.

Y5. REVIEW LOGIC (replaces REQUIRED REVIEW LOGIC sections 1 to 9 on this route; section numbers are fixed; put the bracketed title in the JSON)
1. (Bank Reconciliation Review - MYOB Coding report) Table: each bank, credit card and loan account in the Trial balance with its period-end balance, and the Coding report total for the period (nil, or the items listed: date, account, description, amount). Any unallocated transaction dated on or before period end: High; Bank Rec Completed = No. An item covered by a valid "Override unreconciled" update (as defined in PRE-REVIEW MODE test (a), with the amount matching in Y9): Medium, marked "Overridden by <name> on <date>: <reason>"; Bank Rec Completed stays No; one High Risks row (Medium) whose Required Action is "Allocate in MYOB, or reviewer to accept the override", quoting the override verbatim; items the override does not cover stay High. Coding report empty for the period: Bank Rec Completed = Yes, Completed / Low Risk. Duplicates on bank accounts: same date, amount and description in the General ledger; apply the Xero severity rules, treating a line as a bank-feed line when the General ledger shows it came from the feed (feed references, matched bank transactions) and otherwise as manually entered: High if manual with GST, Medium if manual without GST, Low if bank-feed. State once under the table: "Bank balances not agreed to bank statements - the Coding report confirms all transactions are coded, not that MYOB agrees to the bank." There is no feed-gap or statements-missing test, no statement-balance tie-out and no "Calculated balance out by" sentence on this route. Coding report missing from the pack: "Unable to confirm", Bank Rec Completed = Unable to Confirm, High. An item in an account-wide override's frozen set (Y4): Medium, marked "Overridden (account-wide) by <name> on <date>", with one High Risks row (Medium) for the account quoting the override verbatim, with the count and total of items still open.
2. (Fixed Asset Review - MYOB) MYOB has no depreciation module and no live register: say so. Show the fixed-asset cost and accumulated depreciation accounts from the Trial balance and their movement in the General ledger during the period; use a client fixed asset register only if one is attached, and reconcile it to the Trial balance (any difference: red row, Medium). The "depreciation not run" test does not apply. Possible unrecorded assets from the General ledger: every single supplier line of $1,000 or more incl. GST coded to an expense account with GST, where the contact or description matches the asset-keyword list (electronics and office retailers, vehicle dealers, equipment suppliers, "laptop", "MacBook", "iPad", "printer", "fit-out"; Bunnings excluded) or the account is Repairs & Maintenance / Office Expenses; where the prior-period Profit & Loss or the ledger shows the client consistently expenses that type of item, note it as consistent practice and do not flag, otherwise Medium "assess for capitalisation". A new loan / HP liability account in the Trial balance this period with no movement in the related asset cost account: Medium. Motor vehicle cost increase above the car limit for the income year (confirm the current figure on ato.gov.au): the 1/11th car-limit GST cap check, unless the vehicle is excluded. Capital purchases must be at G10 (CAP code), not G11: a capital item at G11 is Medium.
3. (Profit and Loss Comparison) As Xero Section 3 from the Profit & Loss report (current period vs the previous period of the same length), with the 30% and $1,000 tests and the General Expenses check; list the General Expenses transactions from the General ledger (date, contact, amount, tax code) as MYOB references. Never use the Trial balance's P&L lines. If the file's current financial year (lock date screenshot, Financial year section) is behind the BAS period, add a Low file-maintenance note "MYOB financial year not rolled over - current FY shows <year>; roll over before year-end work" (no High Risks row; it does not block lodgement). Depreciation movement: state it, or "no depreciation posted in the period".
4. (GST Reconciliation Review - MYOB) Rows: GST control accounts at period end from the Trial balance (GST Collected, GST Paid and any other GST liability account, shown separately and as a net); cash basis only: add GST in payables (Payables reconciliation with tax) and less GST in receivables (Receivables reconciliation with tax); Expected net GST position; "1A less 1B (GST report, <basis> basis)"; Variance (expected net less the GST report net). Cross-check the GST report totals to the GST return report and list any difference over $1. Receivables/payables rules: nil trade debtors or creditors in the Trial balance: the reconciliation is not required, show "No receivables/payables at period end"; non-zero and the report provided: use its GST and check its total to the control account (a difference is its own row); non-zero, report missing, cash basis: that row is "Unable to verify - GST content unknown, Receivables/Payables reconciliation with tax not provided", Medium, never $0; non-zero, report missing, accrual basis: Low note only. Accrual basis: GST control = 1A - 1B. Thresholds and wording as Xero Section 4: under $1 no conclusion; $1,000 or less capture it and explain in GST Variance Explanation; over $1,000 investigate, High (red). GST accounts the client clears to an ATO clearing account at lodgement: show the amounts already cleared as their own row and refer to Section {{sec:6}}. The Executive Summary GST Variance is this variance.
5. (Balance Sheet Review - MYOB) From the Trial balance and General ledger, as Xero Section 5: a suspense, clearing or undeposited funds balance at period end: High; Wages Payable or Payroll clearing balance: High (Low with the reason if it is only the last pay run's net pay cleared after period end); rounding over $10: Medium; loan/HP principal repayments must be N-T (BAS excluded): any with GST or FRE is a Medium coding error; transfers to or from accounts not in the Trial balance (for example a director's personal account) must be coded to a loan or equity account, not income or expense: otherwise Medium. MYOB has no draft transactions: say "MYOB has no draft transactions". Audit trail, if attached: a change after period end to a transaction dated in or before the period: Medium if it affects GST, a bank account or a control account, else Low; list them.
6. (ATO ICA Balance Review) ICA CSV cell F4 vs the ATO / Integrated Client Account clearing account in the Trial balance, adjusted for post-period items visible in the CSV, as Xero Section 6. Where the file has no ICA account (GST and PAYGW liabilities are cleared at payment), compare the CSV to the prior AS amount less ATO payments in the period and say so. Reconciles: table only. Does not: one or two sentences, Medium; High if $1,000 or more is unexplained. List any payment plan, overdue balance or GIC visible in the CSV.
7. (Activity Statement Comparison) As Xero Section 7, except: current G1, 1A and 1B come from the GST report (whole dollars), cross-checked to the GST return report (state any difference under the table); W1 and W2 come from the Payroll summary (Section 8); T1 = G1 - 1A; T2, T7 and the three PAYG instalment cases, including "Preparer to choose", exactly as on the Xero route, from the current AS (or an [ICA+BAS attached] update that states them); 7D as on the Xero route, computing from fuel lines in the General ledger only where the Task gives no FTC figure, litres never from dollar spend. Under the table: "G1, 1A, 1B from the MYOB GST report (<basis> basis), cross-checked to the GST return report".
8. (Wages Analysis - MYOB Payroll summary) Columns: Label | Current | Commentary. W1 = gross wages less pre-tax salary sacrifice and W2 = PAYG withheld from the Payroll summary report for the withholding period(s) on the AS (monthly or quarterly per the task name; for monthly PAYGW show each month). Cross-check wages and superannuation expense in the Profit & Loss to the summary, and W2 for earlier months of the quarter to the ICA where PAYGW is lodged monthly; a month with no IAS in the ICA: Medium. No sign of payroll (prior AS W1/W2 nil and no wages, super or PAYGW postings in the ledger): "No payroll - N/A", W1/W2 nil. Signs of payroll but the Payroll summary missing: W1/W2 "Unable to verify - Payroll summary not provided", Medium. State "MYOB Payroll summary report was used".
9. (GST Integrity & Coding Review - MYOB tax codes) Apply the Xero rule set to the GST report detail by MYOB tax code (GST, FRE, N-T, CAP, INP, ITS, EXP, GNR and the file's own codes), building the exceptions yourself: GST applied on bank fees, ASIC fees, loan/HP principal, wages and super, ATO payments, internal transfers, interest, rego, fines/penalties; GST missing on merchant fees and on standard-rated income/expenses; tolls/parking in Motor Vehicle accounts; Light Meals over $100 with GST; insurance at full 1/11; capital items at G11 (GST instead of CAP); FRE on suppliers that normally charge GST (fuel, telco, electricity). Private-looking spend in a business bank account (liquor, ATM withdrawals, personal transfers) coded with GST: flag per the Xero severity rules. Severity, output table and the 1A/G1 and 1B/expense-base ratios as Xero Section 9, with MYOB references as evidence.
10. High Risks Table: unchanged, with MYOB references in the Evidence column.

Y6. MYOB REFERENCES (no deep links)
MYOB has no record URLs in the export. Wherever the Xero route would put a link (Executive Summary bullets, key risk drivers, section tables, High Risks Table), reference the item in plain text as "date · description · amount · MYOB account". Add to the memo JSON: "legendExtra": "MYOB has no record links: flagged items are referenced as date · description · amount · MYOB account." Section links ({{sec:N}}) still apply.

Y7. MEMO CONTENT CHANGES
- Title as on the Xero route.
- meta Client: "<client>, ABN, MYOB file <business name on the reports> confirmed (export pack)". Period: period, GST basis (Y3), withholding frequency, AS document ID, due date. Sources: the pack file name and the date it was attached, the reports used or missing (naming any conditional report not needed and why), prior AS, ICA CSV, "Xero bundle: not used (MYOB)".
- lockPeriods: "MYOB lock date is [date], [matching/preceding] the BAS period end - [locked, no action / not locked through the period end, confirm before lodgement]", adding "('Prevent changes prior to the lock date' ticked)" or "(not ticked)" as the screenshot shows. Screenshot missing: "Lock date not confirmed - screenshot not provided" (information only, no High Risks row). Then: "Audit trail: [n] changes after period end - [none affect GST / list in Section {{sec:5}}]" or "Audit trail not provided - late-change test not run" (information only).
- usage: "MYOB route: pack <zip name>; no Xero calls; <n> agent tool calls".
- Everything else in EXECUTIVE SUMMARY CONTENT is unchanged, including the "PAYG instalment - Preparer to choose" bullet when Section 7 shows both options.

Y8. REVIEW MODE WORKFLOW (MYOB route)
1. Call AS task files and decide the route (ROUTE). Determine the client and BAS period from taskName, then download and unzip the files (Y1) and run the identity check (Y2) and the GST basis check (Y3).
2. Fetch the renderer as in WORKFLOW step 3.
3. Run the gate (Y4), complete Y5, write the memo JSON (/tmp/render/memo.json) with Y6 and Y7, and render to /mnt/session/outputs/BAS_Review_Memo_<Client>_<Period>.pdf (same renderer rules as WORKFLOW step 4).
4. Post the completion update as in WORKFLOW step 5, with a line "Route: MYOB - pack <zip name> (attached <date>), GST basis <Cash/Accrual>" after the number of High items. In the usage block: "runId":null, "adHocXeroCalls":0, "bundleXeroCalls":0, "bundleMakeOperations":0, and add "route":"myob" as the last key.
5. Last: set Status to In Progress.
If anything blocks part of the review, still produce the memo and flag the limitation, as on the Xero route.

Y9. PRE-REVIEW MODE (MYOB route)
PRE-REVIEW MODE applies with these changes.
- STEP 1: unchanged (the filled memo is found and read the same way). Also note the created_at of the newest Prefilled BAS for the period, if one exists (Prefilled_BAS_<Client>_<Period>.pdf or ..._v<n>.pdf).
- STEP 2: there is no bundle. Download the newest MYOB export pack on the Task and rerun Y1 to Y4 on it ("bundle rerun" = re-read the latest pack). If no pack can be read, post an update whose first line is "Pre-Review recheck - <Period> - NOT COMPLETED", saying why, add the usage block (recheckOutcome "not_completed") and set Status to In Progress.
- Changes in MYOB after the review (checked before the tests). Read Notes to Reviewer. If they say anything was changed, fixed, recoded, allocated or re-exported in MYOB ("Fixed in MYOB", "recoded", "allocated the $320 line", "lock date moved" and the like) and no pack was attached after the memo being rechecked was created (created_at), do not run the tests and do not write a memo: post an update whose first line is "Pre-Review recheck - <Period> - NOT COMPLETED", then "Fresh MYOB pack needed: Notes to Reviewer say MYOB was changed (\"<note quoted verbatim>\"), but the newest pack (<zip name>, attached <date>) is older than memo v<n>, so the recheck cannot see those changes.", then "Unlock the period, make the fixes, set the lock date back to the period end, re-export the whole pack for the same period with a new lock date screenshot, attach it to a new update on this task with the same zip name, then move the Task to Pre-Review again.", then the usage block (recheckOutcome "not_completed", failedTests empty, atoPayable null), and set Status to In Progress. It never counts towards the two-failure limit. The same applies after a Prefilled BAS: if a Prefilled BAS exists for the period and no pack was attached after it, and the notes say MYOB was changed, the outcome is this NOT COMPLETED.
- Stale pack (the notes do not say MYOB was changed): if the newest pack was attached before the memo being rechecked was created, still run the recheck on it. If all four tests pass, the outcome is PASS as usual, with this line in the update after the test lines: "This recheck used the MYOB export pack <zip name> attached <date>, before memo v<n>; changes made in MYOB after that are not visible." If any test would fail, do not record a FAIL and do not write a memo: post an update whose first line is "Pre-Review recheck - <Period> - NOT COMPLETED", then "The newest MYOB export pack (<zip name>, attached <date>) is older than memo v<n>, so this recheck cannot see changes made in MYOB since then.", then each test that would have failed with its one-line reason, then "Export a fresh pack from MYOB (all reports for the same period and a new lock date screenshot), attach it to an update on this task, then move the Task to Pre-Review again.", then the usage block (recheckOutcome "not_completed", failedTests empty), and set Status to In Progress. A stale-pack NOT COMPLETED never counts towards the two-failure limit.
- Test (a): the Y4 Coding report gate only. The Coding report in the recheck pack has no unallocated transaction dated on or before period end, or every such item is covered by a valid "Override unreconciled" update as defined in PRE-REVIEW MODE test (a) (same wording, same authors - the Task's Preparer or a manager or partner in staff_roles, validated by the gate's "Override unreconciled applied: ..." update - no amount limit, posted at any time). Each listed amount covers every Coding report item of that amount (ignoring sign) dated on or before period end. Any unallocated item whose amount is not listed is FAIL (a). Notes to Reviewer cannot excuse an unallocated item. The feed-gap sentence of test (a) does not apply. On the test (a) line, quote the override verbatim with its author and date, then list each covered item as account | date | amount | description, with their total. An account-wide override covers only the items in its frozen set (Y4); on the test (a) line give the account, cut-off date, and the number and total of covered items still open, and say the full list is in Section 1 of the memo.
- Test (b): G1, 1A, 1B from the recheck pack's GST report (Y3 basis) and W1, W2 from its Payroll summary against the memo's Section 7 Current column, as on the Xero route. A GST report run on the wrong basis (Y3) fails (b).
- Tests (c) and (d): unchanged, applying Y5 to the recheck pack. A period still unlocked in the new lock date screenshot is a new Medium item: list it in the update and show it in the Prefilled BAS instructions; on its own it does not fail the recheck.
- The PAYGI choice check: unchanged.
- PASS: produce the Prefilled BAS as in STEP 4 PASS items 1, 2, 3, 4, 6, 7 and 8, with these changes. Figures come from the recheck pack on the client's basis (Y3). Purpose: "BAS for importation in XPM". Sources: filled memo file name and version, the MYOB export pack file name and the date it was attached, prior AS, ICA CSV, "recheck bundle: not used (MYOB)". No bundle runId. If an override was applied, the instructions carry the "Bank reconciliation not complete - Override unreconciled by <name> on <date>:" line with the covered items and the reason verbatim, as on the Xero route. There is no Make tool for MYOB: never call tool 6 and never create anything in MYOB. Instead of the Draft ATO payable section, add the manual-entry table per claude_Xero-Bill-Draft-Procedure.md headed "ATO payable - for manual entry in MYOB (not created by Claude)": contact Australian Taxation Office; bill date the day after period end; due date from the current AS (blank and flagged if not shown); reference "BAS <Quarter/Month> <Year> - <business name>"; lines GST (1A - 1B as adjusted, to the file's GST liability account(s) named from the Trial balance, or "confirm in MYOB"), PAYG Withholding (W2, to the PAYG withholding payable account), Income Tax Payable - PAYG instalment (T11 or T7), Fuel Tax Credit (7D, negative, if any); total = label 9 (payable or refund). Never fabricate an account name: name only accounts that appear in the Trial balance. In the completion update, replace the Draft ATO payable line with "ATO payable: manual-entry table in the Prefilled BAS (no MYOB write tool). Please enter it in MYOB and finalise in XPM."
- Prefilled BAS v2: if a Prefilled BAS already exists for the period (STEP 1) and this recheck passes on a pack attached after it, render the new one as /mnt/session/outputs/Prefilled_BAS_<Client>_<Period>_v<n+1>.pdf with title "Prefilled BAS - <BAS period> - <Client> - v<n+1>", a meta row ["Version", "v<n+1> - supersedes v<n> (MYOB changed after the first Prefilled BAS)"], the Preparer's note on the change quoted verbatim in the instructions, and a fresh manual-entry table; say in the completion update that it supersedes the earlier Prefilled BAS and that any ATO payable already entered in MYOB from v<n> must be corrected to v<n+1>.
- FAIL and ESCALATED: unchanged, applying Y5 to Y7 to memo v<n+1> (never on a stale pack: see above).
- Usage block: as in STEP 6 with "runId":null, "bundleXeroCalls":0, "bundleMakeOperations":0, "atoPayable":"manual" on PASS (null otherwise), "overrideUnreconciled" as applied or null, and "route":"myob" added as the last key.
