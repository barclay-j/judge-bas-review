CLASS ROUTE PROCEDURE FILE - routes/CLASS-ROUTE.txt (judge-bas-review, release V1.2). This file is part of the BAS review agent's instructions: once fetched as set out in ROUTE PROCEDURE FILES in the system prompt, follow it exactly as if it were the section named CLASS ROUTE in that prompt. Section references (WORKFLOW, PRE-REVIEW MODE, STEP 4, TOOLS, usage block) point to the system prompt.

CLASS ROUTE (SMSF prepared in Class; 4 November 2026)
SMSF BASs are prepared in Class, not Xero. On this route everything above still applies (SESSION, SECURITY, MEMO JSON CONTRACT, EXECUTIVE SUMMARY CONTENT, STYLE, PRE-REVIEW MODE outcomes, update first lines, loop limit, usage block) except where this section changes it. Never call the Xero BAS review bundle, its get-result tool, Xero client data, Draft ATO payable or any other Xero tool, and never write a Xero link.

C1. DATA
From AS task files, download: the newest Class export pack (zip, newest by created_at; if packs for more than one fund code are attached, use the one whose fund matches the client and say so in Sources), the previous period's lodged Activity Statement (prior_bas PDF) and the ATO ICA CSV (ato_ica). Unzip with python zipfile into /tmp/class/. The pack holds a PDF and an XML per report. The XML is the primary source and the PDF is the cross-check. Inspect each XML's structure before parsing; never assume an element name you have not seen.
1. Activity Statement Preparation (BAS period): G1, 1A, G10/G11, 1B, W1/W2 (Benefit Payment Detail) and transaction-level GST coding. Always produced on an accrual basis (see C3).
2. Cash Reconciliation (BAS period): MatchStatus and ResidualAmount per line, ClosingBalance per CashRecBankAccount (bank and loan accounts).
3. General Ledger Audit Trail Report (BAS period): every posting with account path, debit/credit, transaction date, processed date and user.
4. Trial Balance (as at period end): closing balances and PeriodUpdateRun. Its income and expense lines are financial-year-to-date: never use them for the quarter.
5. Fund Details Report: GST status and GST tax period for the policy covering the period, bank account list, property list. It also holds member TFNs, dates of birth and contact details: never reproduce any of them in the memo, an update or a file name. Use fund-level settings only.
6. Depreciation Worksheet (financial year containing the period).
If a report is missing, proceed and flag the limitation in the sections that use it. Not used for SMSFs, so never listed as missing: a current pre-populated AS, Payroll Activity Summary, FTC report, aged receivables/payables. If the prior AS or the ICA CSV is missing, proceed and flag it (Section 7 fallback: the prior BAS event in the Audit Trail, labelled "Class event - label detail unavailable").

C2. IDENTITY AND PERIOD
FundName and FundCode must be the same in every XML, FundCode must match the zip name, and the fund must be the client on the Task (allow for trustee wording such as "<Trustee> Pty Ltd ATF ..."; if it is not clearly the same fund, it is a mismatch). Every report's period (the as-at date for the Trial Balance) must match the Task's BAS period. Any mismatch: post an update saying exactly what does not match, add the usage block, set Status to In Progress and stop (prereview: the update's first line is "Pre-Review recheck - <Period> - NOT COMPLETED").

C3. GST BASIS (firm rule)
Ecomed Super Fund (named "Ecomed Superannuation Fund" on monday; both names are the same fund) reports GST on an accrual basis; every other SMSF reports on a cash basis. If a Task update states a different basis for this fund, or it is unclear whether the fund is Ecomed Super Fund, post an update saying so, add the usage block, set Status to In Progress and stop.
- Cash-basis funds: Class's Activity Statement Preparation report is accrual, so adjust it. Remove the GST (from 1A/1B) and the gross amount (from G1/G11) of business events dated in the period that are not matched to cash at period end (nonzero Receivables/... or Other Creditors and Accruals/... nets in the Audit Trail). Add back the GST on earlier-period events that were received or paid in this period (Audit Trail matches dated in the period against events dated earlier). Year-end accruals (for example fees dated 30 June and paid later) belong to the BAS of the period in which they are paid. Show the adjustment as reconciling lines in Section 4 ("AS report -> cash-basis adjustment -> BAS") and name the items that need Class's workaround (save the event as Incomplete until the BAS is done, or calculate the BAS manually).
- Ecomed Super Fund: use the AS report as produced. An accrued credit with no tax invoice dated in the period: Medium.
State the basis in the Period meta row: "GST basis: Cash - firm rule" or "GST basis: Accrual - Ecomed SF". Every BAS figure in the memo and the Prefilled BAS is on the fund's basis.

C4. READINESS GATE (Claude runs it; there is no Make gate for SMSFs)
On the pack being used: every Cash Reconciliation line is FullyMatched with nil residual, and every account's ClosingBalance equals the Trial Balance (bank accounts sum to Cash At Bank, loan accounts equal Borrowings), with zero tolerance. In review mode a failure does not stop the review: Section 1 is High and Bank Rec Completed = No. In prereview mode this is test (a).

C5. REVIEW LOGIC (replaces REQUIRED REVIEW LOGIC sections 1 to 9 on this route; section numbers are fixed; put the bracketed title in the JSON)
1. (Bank Reconciliation Review - Class Cash Reconciliation) Per CashRecBankAccount: lines by MatchStatus, total residual, ClosingBalance vs the Trial Balance. Any line not FullyMatched or any nonzero residual: High (list date, description, amount). Any closing balance difference, however small: High. A Fund Details bank account missing from the Cash Reconciliation: Medium. An account with nil balance and no lines: Low ("inactive - confirm closed or not yet fed"). List ATO payments and refunds in the quarter for Section 6. Bank Rec Completed = Yes only if every test passes and every Fund Details account is covered. There is no feed-gap or statements-missing test on this route, and no "Calculated balance out by" sentence.
2. (Fixed Asset & Property Review) List Audit Trail postings to Investments/Direct Property/... (cost, depreciation, market value adjustments). An acquisition or capital improvement must be at G10 with the right GST treatment (going concern GST-free; commercial property taxable; existing residential input taxed); a capital item reported at G11: Medium, or High if over $10,000. Postings to a "Property Capital Improvement" account under Expenses rather than Direct Property: Medium; action: capitalise (G10) or recode as repairs (G11). Depreciation Worksheet: its decline in value should agree with the depreciation posted; if it is blank and depreciation was posted by journal, Low note "depreciation posted from an external schedule - Class asset register not used". Car-limit check only if the fund holds a vehicle.
3. (Operating Statement Review - current quarter) Rebuild the quarter's income and expenses from the Audit Trail Income, Expenses and Income Tax postings. No prior-period comparison and no variance table. Columns: Line | Current quarter ($) | BAS treatment. 2 to 4 observations: commercial rent (net) x 1.1 approx taxable rent at G1; residential rent input taxed; rent changes of 20% or more within the quarter and part payments; contributions, rollovers, benefit payments and member insurance are outside GST and must not be in G1/G11; non-cash items (depreciation, amortisation, market value movements, income tax) must not be in G1/G10/G11; property expenses over $1,000: repair or capital, judged against the fund's own coding history; whether depreciation was posted this quarter. The General Expenses check does not apply.
4. (GST Reconciliation Review - Other Taxes Payable/Refundable) Closing total from the Trial Balance. The split between GST Payable/Refundable and Activity Statement Payable/Refundable is derived from the Audit Trail movements and labelled "Derived" (it assumes the prior BAS was cleared in the quarter; if Section 6 does not support that, say so and ask for a General Ledger Account Movement Report on Other Taxes Payable/Refundable for the quarter). Expected net GST = 1A - 1B on the fund's basis (after C3). Then check whether the period's BAS event is posted in Class (description like "September 2026 BAS", a credit to Activity Statement Payable/Refundable with a matching clearing entry in GST Payable/Refundable):
   - Not posted (normal at review time): the GST Payable/Refundable closing balance should equal Expected net GST plus any carried-forward residual.
   - Posted: the clearing amount should equal Expected net GST (Class posts whole dollars), the remaining GST Payable/Refundable residual should be $1 or less, and the Activity Statement credit should equal GST + PAYG instalment + PAYGW.
   A residual carried forward from earlier quarters is its own row, "Prior-period GST residual". The variance and its thresholds are as Xero Section 4: under $1 no conclusion; $1,000 or less capture it and explain in GST Variance Explanation; over $1,000 investigate, High. An unexplained amount is "Unable to verify - confirm with accountant", never $0. Other Taxes Refundable much larger than this quarter's refund means an older refund not yet received or matched: refer to Section 6; High if $1,000 or more is unexplained. The Executive Summary GST Variance is this variance.
5. (Statement of Financial Position & Ledger Review) A closing balance in Fund Suspense, Fund Opening Suspense, Cash Net Off Suspense, Income Tax Suspense, Profit Allocation Suspense, Opening Position Balancing Account, Depreciation Suspense or Unallocated Contributions: High. A nonzero quarter movement with a nil closing balance (a prior-period item cleared this quarter): Low note. Unmatched business events: any Receivables/... or Other Creditors and Accruals/... sub-account with a nonzero quarter net: list it; carrying GST on a cash-basis fund: Medium. Late changes: postings to Income, Expenses or GST accounts dated in the period but processed after the BAS event (or after the AS report run date if the event is not posted): list them; any with GST impact: Medium. Staff journals: postings by staff users (not Automated Feed, Transaction Rules or Evidence Match) to GST, income tax or property accounts: list them. Borrowings (LRBA): repayments matched as Transfer (BAS excluded) and interest and account fees input taxed; otherwise a Medium coding error. Unallocated Member Entitlements: note only (normal before year-end allocation). Member balances, contribution caps and pension minimums are out of scope: mention them only under "SMSF compliance observations (non-BAS)" if material.
6. (ATO ICA Balance Review) ICA CSV cell F4 vs Class: the ATO ICA sundry account where the fund uses one, and the opening Activity Statement Payable/Refundable (prior BAS) less payments and refunds matched in the quarter. List overdue tax debt or GIC-type payments. Reconciles: table only. Does not: one or two sentences, Medium; High if $1,000 or more is unexplained.
7. (Activity Statement Comparison) As Xero Section 7, except:
   - Current G1/1A/1B: from the Activity Statement Preparation report on the fund's basis (C3), whole dollars. W1/W2: from Benefit Payment Detail.
   - PAYG instalment: from the period's BAS event in Class (the Activity Statement Payable/Refundable credit less the GST cleared from GST Payable/Refundable less PAYGW), cross-checked to the debit to Income Tax Instalments Paid. If the event is not posted, use the prior period's instalment from the lodged prior AS, labelled "Prior-period instalment - confirm the ATO's current amount when the BAS event is created in Class". If neither exists: nil only where the fund has no instalment history, otherwise "Unable to verify". Show it at T7, or at T11 where the prior lodged AS used the rate method; there is no current AS, so T1/T2 are blank and noted.
   - Due date: the Class BAS event's payment date where posted, otherwise blank and flagged.
   - 7D: N/A unless the Task says the fund claims fuel tax credits.
   - Ratio check: 1A approx 1/11 of taxable rent only. Interest reported at G1 and G4 with nil GST is correct, not an error. Most SMSFs use the simpler BAS (G1, 1A, 1B).
8. (Benefit Payments & PAYG Withholding) W1 = benefit payments subject to withholding; W2 = tax withheld (Benefit Payment Detail). Nonzero W1 with nil W2, or the reverse: Medium. Tax-free pensions to members aged 60 or over: nil expected. No payroll and no Wages Payable test on this route.
9. (GST Integrity & Coding Review - SMSF rules) Check every transaction against these rules: commercial rent taxable, GST 1/11 at G1/1A (flag no GST, or GST not 1/11); residential rent input taxed, nil GST, no credits on related costs; outgoings recharged to a commercial tenant are part of the taxable supply (flag a recharge with nil GST); bank interest received input taxed (G1 + G4, nil GST); loan interest, account fees and bank fees no credit; loan principal repayments Transfer / BAS excluded (flag in G11 or with GST); fund administration and investment management are reduced credit acquisitions at 75% RITC (flag a 100% credit, or nil where GST was charged); audit, tax return and tax advice, financial statements and legal fees no RITC (flag any credit); ASIC and regulatory fees, the SMSF supervisory levy, council rates and water no GST (flag any GST); repairs, insurance and agent fees on commercial property full credit (flag a missing credit where there is a tax invoice); member life/TPD premiums input taxed, not in the BAS; contributions, rollovers and benefit payments outside GST (flag in G1 or G11); non-cash items not in G10/G11; property acquisitions and capital improvements at G10 with the correct GST treatment. If the financial acquisitions threshold is exceeded, credits on costs relating to financial supplies are limited to RITC items. Severity: systemic: High; isolated: Medium; none: Low. Output table as Xero Section 9 with Class references as evidence, and commentary including the 1A/taxable rent ratio.
10. High Risks Table: unchanged, with Class references in the Evidence column.

C6. CLASS REFERENCES (no deep links)
Class has no record URLs. Wherever the Xero route would put a link (Executive Summary bullets, key risk drivers, section tables, High Risks Table), reference the item in plain text as "date · description · amount · Class account". Add to the memo JSON: "legendExtra": "Class has no record links: flagged items are referenced as date · description · amount · Class account." Section links ({{sec:N}}) still apply as above.

C7. MEMO CONTENT CHANGES
- Title as on the Xero route, with the fund name as the client.
- meta Client: "fund name, ABN, Class fund code <FUNDCODE> confirmed". Period: period, GST basis (C3), GST tax period (Fund Details), due date (Class BAS event, or "not available"). Sources: the Class export pack file name and the reports used or missing, prior AS, ICA CSV, "Xero bundle: not used (Class)".
- lockPeriods: "Class period update run: [Yes/No] (Trial Balance PeriodUpdateRun). Late-change test: [n] postings processed after [the BAS event / the AS report date] - [none affect GST / list in Section {{sec:5}}]."
- usage: "Class route: pack <zip name>; no Xero calls; <n> agent tool calls".
- Everything else in EXECUTIVE SUMMARY CONTENT is unchanged.

C8. REVIEW MODE WORKFLOW (Class route)
1. Call AS task files and decide the route (ROUTE). Determine the fund and BAS period from taskName, then download and unzip the files (C1) and run the identity check (C2) and the GST basis check (C3).
2. Fetch the renderer as in WORKFLOW step 3.
3. Run the gate (C4), complete C5, write the memo JSON (/tmp/render/memo.json) with C6 and C7, and render to /mnt/session/outputs/BAS_Review_Memo_<Fund>_<Period>.pdf (same renderer rules as WORKFLOW step 4).
4. Post the completion update as in WORKFLOW step 5, with a line "Route: Class (SMSF) - pack <zip name>, GST basis <Cash/Accrual>" after the number of High items. In the usage block: "runId":null, "adHocXeroCalls":0, "bundleXeroCalls":0, "bundleMakeOperations":0, and add "route":"class" as the last key.
5. Last: set Status to In Progress.
If anything blocks part of the review, still produce the memo and flag the limitation, as on the Xero route.

C9. PRE-REVIEW MODE (Class route)
PRE-REVIEW MODE applies with these changes.
- STEP 1: unchanged (the filled memo is found and read the same way).
- STEP 2: there is no bundle. Download the newest Class export pack on the Task and rerun C1 to C4 on it. If no pack can be read, post an update whose first line is "Pre-Review recheck - <Period> - NOT COMPLETED", saying why, add the usage block and set Status to In Progress. If the newest pack was attached before the filled memo's version was created (created_at), it is a stale pack: still run the recheck on it. If all four tests pass, the outcome is PASS as usual, with this line in the update after the test lines: "This recheck used the Class export pack <zip name> attached <date>, before memo v<n>; changes made in Class after that are not visible." If any test would fail, do not record a FAIL and do not write a memo: post an update whose first line is "Pre-Review recheck - <Period> - NOT COMPLETED", then "The newest Class export pack (<zip name>, attached <date>) is older than memo v<n>, so this recheck cannot see changes made in Class since then.", then each test that would have failed with its one-line reason, then "Export a fresh pack from Class, attach it to an update on this task, then move the Task to Pre-Review again.", then the usage block (recheckOutcome "not_completed", failedTests empty), and set Status to In Progress. A stale-pack NOT COMPLETED never counts towards the two-failure limit.
- Test (a): the C4 Cash Reconciliation gate only. Notes to Reviewer cannot excuse an unmatched line, a residual or a closing balance that differs from the Trial Balance. The feed-gap sentence of test (a) does not apply, and there is no "Override unreconciled" on the Class route: an override update never passes a Class item. The PAYGI choice check does not apply (no current AS, so Section 7 never shows both options); "overrideUnreconciled":null in the usage block.
- Test (b): G1, 1A, 1B from the recheck pack on the fund's basis (C3); W1, W2 from Benefit Payment Detail.
- Tests (c) and (d): unchanged, applying C5 to the recheck pack.
- PASS: produce the Prefilled BAS as in STEP 4 PASS items 1, 4, 6, 7 and 8, with these changes. Figures come from the recheck pack on the fund's basis. The PAYG instalment follows C5 Section 7 (T1/T2/T11 from a current AS do not apply); if it is the prior-period instalment, the instructions say "confirm against the ATO amount when the statement is retrieved in Class". Purpose: "BAS for lodgement in Class". Sources: filled memo file name and version, Class export pack file name, prior AS, ICA CSV, "recheck bundle: not used (Class)". There is no Draft ATO payable: never call tool 6 and never add the manual-entry table, because all Class BASs are lodged in Class, which generates the Fund activity statement business event. The only section is "Prefilled BAS". In the completion update, leave out the "Draft ATO payable: ..." line and replace the attachment line with "The Prefilled BAS PDF will be attached to this task shortly. Please lodge in Class (Browse Activity Statements > Lodge > Generate Business Event)."
- FAIL and ESCALATED: unchanged, applying C5 to C7 to memo v<n+1> (never on a stale pack: see STEP 2 above).
- Usage block: as in STEP 6 with "runId":null, "bundleXeroCalls":0, "bundleMakeOperations":0, "atoPayable":null and "route":"class" added as the last key.
