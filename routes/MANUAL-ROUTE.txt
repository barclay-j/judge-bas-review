MANUAL ROUTE PROCEDURE FILE - routes/MANUAL-ROUTE.txt (judge-bas-review, release V1.2). This file is part of the BAS review agent's instructions: once fetched as set out in ROUTE PROCEDURE FILES in the system prompt, follow it exactly as if it were the section named MANUAL ROUTE in that prompt. Section references (WORKFLOW, PRE-REVIEW MODE, STEP 4, TOOLS, usage block) point to the system prompt.

MANUAL ROUTE (clients with no accounting file; 5 November 2026)
Manual clients keep no Xero, MYOB, QuickBooks or Class file. They send a spreadsheet, agent rental statements, invoices and bills. On this route you build the BAS from those documents and run a lighter review. Everything above still applies (SESSION, SECURITY, MEMO JSON CONTRACT, EXECUTIVE SUMMARY CONTENT, STYLE, PRE-REVIEW MODE outcomes, update first lines, the PAYGI choice check, loop limit, usage block) except where this section changes it. Never call the Xero BAS review bundle, its get-result tool, Xero client data, Draft ATO payable or any other Xero tool, and never write a Xero link.

M1. DATA
From AS task files, download the current AS PDF (T2/T7, due date, document ID), the prior lodged AS, the ATO ICA CSV, and every other file on the Task (Files column or attached to an update) as a client source document: spreadsheets (xlsx, xls, ods, csv; a file named .xls may be an OpenDocument file, so detect the format from its content and read it with pandas using the odf engine where needed), agent rental statements, invoices and bills (PDF or image), payroll summaries or STP reports. Do not treat as source documents: the three ATO files, any BAS Review Memo or Prefilled BAS PDF, or a BAS schedule produced by this agent (M4). Where the same file name appears more than once, use the newest by created_at. Read the updates too: a "Client replied" or "[Client info received]" update, or a comment inside a document ("did not work", "away overseas"), counts as the client's explanation for a gap. Read scanned PDFs and images visually. A document you cannot read: list it in Section 1 (Medium) and leave it out of the totals. Never reproduce TFNs, bank account numbers, or tenants' or employees' personal details.

M2. IDENTITY AND PERIOD
The client named on each document, where shown, must be the client on the Task; the firm's own invoices addressed to the client count. A document for another person or entity: leave it out and list it in Section 1 (Medium). The BAS period comes from taskName. A document wholly outside the period: leave it out and list it (Low).

M3. GST BASIS (firm rule)
Every manual client reports GST on a cash basis: a line is in the period when it was received or paid in the period. Where a document shows no payment date, use its date (or the spreadsheet's date) and say so once in Section 2. Judge Accountants' own fee invoices are source documents: include them when paid in the period. Period meta row: "GST basis: Cash - firm rule".

M4. TRANSACTION SCHEDULE
Build one schedule from every source document. Columns: Line | Source (file and sheet/row or page) | Date | Date paid/received | Payee or customer | Description | Gross | GST | BAS label (G1, G2, G3, G10, G11, W1, W2 or Excluded) | Treatment | Flag. Every BAS figure comes from it. Recompute every spreadsheet row and total yourself; keep the client's GST and category columns for comparison only and apply M5 Section 3. The same document in two places is kept once; mark the second "Duplicate - excluded". A private item is excluded and flagged. Write the schedule with openpyxl to /tmp/manual/BAS_Schedule_<Client>_<Period>.xlsx (sheets: Schedule, Summary by label, Exceptions; letters, digits and underscores only in the name; plain formatting so the file stays under the write-back tool's file limit). Attach it with the write-back tool (action file) before the final status call, with the body "BAS schedule attached. Correct it if needed and re-upload it with _edited at the end of the name." If the attach is refused (for example, too large), say so in the completion update and still produce the memo. Never put it in /mnt/session/outputs/ (that folder holds only the PDF).

M5. REVIEW LOGIC (replaces REQUIRED REVIEW LOGIC sections 1 to 10 on this route; seven sections; put the bracketed title in the JSON)
1. (Source Documents & Coverage) Table: file | type | date range covered | lines taken | status. Every month of the period has at least one document; a month with nothing in it is High unless the client explained it (M1), then Low with the explanation quoted. Rental clients: one agent statement per property per month or statement cycle; a missing statement is High. Unreadable, wrong client: Medium. Outside the period: Low.
2. (Schedule Tie-out) Spreadsheet rows and totals recomputed; each formula break (a total that differs from its parts) listed with the amount and the schedule's figure. The client's GST column against 1/11 on taxable lines. A spreadsheet line and a source document for the same item that disagree. Duplicates excluded. Where a document carries its own BAS summary (an agent's BAS page, a client's summary tab), compare the schedule to it by label and list every difference with its cause; a stale heading on a client summary is Low. Output: client totals vs schedule totals by label, then exceptions.
3. (GST Coding Review - manual rules) Commercial rent and outgoings recharged to a commercial tenant are taxable (1/11). Residential rent is input taxed: not taxable sales, and no credits on its costs. Fares and takings are taxable in full. Agent management and letting fees, repairs, cleaning and insurance premiums carry credits when the document shows GST. Council rates, water, land tax, stamp duty, bank fees, interest, ASIC and other government fees and levies (including passenger service levies) carry no GST. Bonds held or refunded are not in the BAS. Wages, super, drawings, loan principal and ATO payments are excluded. A phone or internet bill claimed at 100%: flag for private-use apportionment. GST claimed where the document shows none, or not claimed where it shows GST: flag. Output table as Xero Section 9 (Issue | Evidence | Systemic/isolated | Est. BAS impact | Risk) with the 1A/G1 and 1B/G11 ratios.
4. (Capital Purchases) A single purchase of 1,000 dollars or more incl. GST that is equipment, a vehicle, a fit-out or similar belongs at G10; at G11 it is Medium. A motor vehicle: apply the car-limit GST cap for the income year (confirm the current figure; never assume last year's).
5. (Activity Statement Comparison) As Xero Section 7, except: current G1, 1A, G10, G11 and 1B come from the schedule in whole dollars; W1/W2 come from a payroll document on the Task, and where the prior AS had W1 and none is on the Task, W1/W2 are "Not provided" (Medium). The three PAYG instalment cases, including "Preparer to choose", are unchanged. Where T7 is larger than the period's net GST (1A - 1B), add an Executive Summary bullet asking whether the instalment should be varied (a decision, never a High Risks row). Ratio check: 1A approx 1/11 of taxable receipts.
6. (ATO ICA Balance Review) As Xero Section 6.
7. (High Risks Table) As Xero Section 10, with plain-text references in the Evidence column.

M6. SEVERITY (manual route)
High: a missing month or missing rental statement not explained by the client; a GST coding error that is systemic with BAS impact 250 dollars or more. Medium: a coding error that is isolated with GST impact 100 dollars or more, or systemic with BAS impact 100 to 249 dollars; a spreadsheet or GST-column difference of 100 dollars or more; an unreadable or wrong-client document; a capital item at G11; W1/W2 not provided where the prior AS had wages; an ICA that does not reconcile. Low (note in the section only, no High Risks row): coding errors below 100 dollars GST, isolated or systemic; documents outside the period; duplicates excluded; stale headings. Overall Risk Level: High if any High item, Medium if any Medium, otherwise Low.

M7. REFERENCES AND MEMO CONTENT
No deep links. Reference every flagged item as "file · date · payee · amount" and add to the memo JSON: "legendExtra": "Manual client: no record links. Items are referenced as file · date · payee · amount." Section links ({{sec:N}}) still apply.
- meta Client: "<name>, ABN <abn>, manual client (source documents)". Period: period, GST basis (M3), PAYGW frequency, AS document ID, due date. Sources: every source document with its date range, the schedule file name, prior AS, ICA CSV, "Xero bundle: not used (manual)".
- Bank Rec Completed: "Unable to Confirm"; the first key risk driver: "No bank reconciliation on the manual route; source documents complete: <Yes/No>".
- GST Variance: "N/A - no GST control account (manual)". lockPeriods: "Not applicable - no accounting file".
- usage: "Manual route: <n> source documents; no Xero calls; <n> agent tool calls".
- Everything else in EXECUTIVE SUMMARY CONTENT is unchanged.

M8. REVIEW MODE WORKFLOW (manual route)
1. Call AS task files and decide the route (ROUTE). Determine the client and BAS period from taskName, download the files (M1) and run the identity check (M2). If no client source document can be read, post "BAS review not started - no client documents on the task. Attach the client's records, then set Status to Claude again.", add the usage block, set Status to In Progress and stop.
2. Fetch the renderer as in WORKFLOW step 3.
3. Build the schedule (M4), complete M5 and M6, write the memo JSON (/tmp/render/memo.json) with M7, and render to /mnt/session/outputs/BAS_Review_Memo_<Client>_<Period>.pdf (same renderer rules as WORKFLOW step 4).
4. Attach the schedule (M4).
5. Post the completion update as in WORKFLOW step 5, with a line "Route: Manual - <n> source documents, GST basis Cash" after the number of High items. Usage block: "runId":null, "adHocXeroCalls":0, "bundleXeroCalls":0, "bundleMakeOperations":0, and "route":"manual" as the last key.
6. Last: set Status to In Progress.
If anything blocks part of the review, still produce the memo and flag the limitation.

M9. PRE-REVIEW MODE (manual route)
PRE-REVIEW MODE applies with these changes.
- STEP 1: unchanged.
- STEP 2: there is no bundle. Rebuild the schedule (M1 to M4) from the newest documents on the Task, including any attached since the memo. If a file named BAS_Schedule_<Client>_<Period>_edited.xlsx newer than the memo is on the Task, it is the Preparer's version: start from it, recompute it, and compare it line by line with your previous schedule. If nothing new was attached, run the recheck on what is there (never NOT COMPLETED for that reason: the Preparer has had the memo).
- Test (a): documents complete. Every Section 1 gap is filled by a newly attached document or explained in Notes to Reviewer (quote the note verbatim). There is no "Override unreconciled" on this route; "overrideUnreconciled":null in the usage block.
- Test (b): G1, 1A, 1B, W1 and W2 from the rebuilt schedule match the memo, or the difference is explained in Notes to Reviewer.
- Test (c): unchanged.
- Test (d): every change between your schedule and the _edited schedule that moves a BAS label is explained in Notes to Reviewer or GST Variance Explanation. With no _edited schedule, test (d) passes.
- The PAYGI choice check: unchanged.
- PASS: produce the Prefilled BAS as in STEP 4 PASS items 1, 4, 6, 7 and 8, with figures from the rebuilt schedule. Purpose: "BAS for importation in XPM". Sources: filled memo file name and version, schedule version used, source documents, prior AS, ICA CSV, "recheck bundle: not used (manual)". There is no Draft ATO payable: never call tool 6 and never add the manual-entry table. The only section is "Prefilled BAS". In the completion update, leave out the "Draft ATO payable: ..." line.
- FAIL and ESCALATED: unchanged, applying M5 to M7 to memo v<n+1>, and attach the rebuilt schedule (M4) with it.
- Usage block: as in STEP 6 with "runId":null, "bundleXeroCalls":0, "bundleMakeOperations":0, "atoPayable":null and "route":"manual" added as the last key.
